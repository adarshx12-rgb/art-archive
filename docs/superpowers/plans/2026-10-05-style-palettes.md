# Style Palettes and Colour Swap Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Every art style gets four palettes of its own, and each palette page gains an AI colour swap that rebuilds the palette around a visitor's chosen colour for a chosen style.

**Architecture:** Palettes stay static content (`PaletteRecord[]`), split into `src/content/palettes/` by style family; the palettes are written by hand in the session, never generated by a script. The swap is a new Worker endpoint `POST /api/swap` (`worker/swap.ts`) that uses the existing `ask()` chain, plus a `ColourSwap` React component on the palette page.

**Tech Stack:** React 19 + react-router 8, Tailwind, Vite 8 + Cloudflare Workers, zod 4, vitest.

**Spec:** `docs/superpowers/specs/2026-10-05-style-palettes-design.md`

## Global Constraints

- Palette content is written by Claude Code during the build, as source files. No script calls OpenRouter or any other paid API to generate it.
- The AI API is used only at runtime, for the live colour swap, through the normal `ask()` chain with `effort: "low"`, covered by the existing `AI_LIMIT`.
- Every palette: 2–4 colours; roles in order — 2: background, primary · 3: background, primary, accent · 4: background, primary, secondary, accent; shares total 100; unique slug across the whole library; `suits` slugs exist in `allStyles`.
- Existing 25 palette slugs and URLs stay unchanged.
- Every one of the 69 styles has at least four palettes whose `suits` includes it, with at least one of 2 or 3 colours and at least one of 4 colours.
- Primary must read against background: `contrastRatio(primary, background) >= 3` for every new palette (web/graphic design use).
- Copy uses the site's voice: curly quotes/apostrophes (’ “ ”), plain sentences.
- Commit messages end with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.

## Review Focus

1. Swapping in the colour the palette already has, or a colour equal to another slot → the request still works and the result keeps the visitor's hex at that index (worker test in Task 1).
2. Model returns the locked slot with a different hex (e.g. "#0000ff" lower-case or a near miss) → the server overwrites it with the visitor's exact normalised hex (Task 1 test).
3. `?s=` naming an unknown or hidden style → the swap's style select falls back to the palette's first suited style; no crash (Task 2 test of `initialSwapStyle`).
4. Visitor types a 3-digit or invalid hex in the text field → 3-digit expands (`#0af` → `#00AAFF`); invalid disables Suggest with a visible message (Task 2 test of `parseHexInput`).
5. Browse page with a `style` param naming an unknown style → the page ignores it and lists all palettes; a known style with no matches under the other filters shows the empty state, whose "Show all palettes" clears the style too (Task 3 test of `filterPalettes`, Task 3 Step 9 browser check).

```ts
import { z } from "zod";
import { getStyle } from "../src/content/styles";
import type { Hex, PaletteRole, PaletteSize } from "../src/content/types";
import { normaliseHex } from "../src/lib/color";
import { ROLE_ORDER } from "../src/lib/prompt/compose";
import { AiError, ask } from "./ai";
import type { Env } from "./env";

const HexIn = z.string().regex(/^#?[0-9a-fA-F]{3}([0-9a-fA-F]{3})?$/);

export const SwapRequest = z
  .object({
    style: z.string().max(80),
    colours: z.array(z.object({ hex: HexIn, name: z.string().max(40) })).min(2).max(4),
    index: z.number().int().min(0),
    hex: HexIn,
  })
  .refine((b) => b.index < b.colours.length);

const SwapOut = z.object({
  palettes: z
    .array(
      z.object({
        name: z.string().describe("A short evocative name, 1-3 words."),
        colours: z.array(z.object({ hex: z.string().describe("Six-digit hex."), name: z.string().describe("Plain colour name, e.g. 'cobalt'.") })),
        why: z.string().describe("One sentence on why it works for the style."),
      }),
    )
    .describe("Exactly three palettes."),
});

const SWAP_SYSTEM = `You rebuild a colour palette around one colour a designer has chosen, for one art style. Return exactly three palettes. Each has the same number of colours as the original, in the same role order (background, primary, then secondary/accent), and keeps the chosen colour exactly, in the same position. Change the other colours so the whole palette works with the chosen colour and stays true to the style's own colour sense (its period, materials, printing and pigments). The three palettes must differ from each other: e.g. one close to the original's mood, one bolder, one quieter. These palettes are used for websites and graphic design: the primary must be clearly legible on the background, the accent is used sparingly, and no two colours should be near-duplicates. Give each colour a plain, specific name a person would say ("cobalt", "oxblood").`;

type Swapped = { name: string; colours: { hex: Hex; name: string; role: PaletteRole }[]; why: string };

/** Three palettes that keep the visitor's colour at `index`; invalid ones are dropped. */
export async function swapColour(env: Env, body: z.infer<typeof SwapRequest>, override?: string | null) {
  const style = getStyle(body.style);
  if (!style) throw new AiError("That style isn’t in the library.", 400, false);
  const locked = normaliseHex(body.hex)!;
  const size = body.colours.length as PaletteSize;
  const roles = ROLE_ORDER[size];
  const input = {
    style: { name: style.name, colour: style.look.colour, swatches: style.swatches.map((s) => `${s.name} ${s.hex}`) },
    original: body.colours.map((c, i) => ({ role: roles[i], hex: normaliseHex(c.hex), name: c.name })),
    keep: { position: body.index + 1, role: roles[body.index], hex: locked },
  };
  const { data, usage, model } = await ask(env, { system: SWAP_SYSTEM, user: JSON.stringify(input), schema: SwapOut, name: "swap", effort: "low" }, override);

  const seen = new Set<string>();
  const palettes: Swapped[] = [];
  for (const p of data.palettes) {
    if (p.colours.length !== size) continue;
    const hexes = p.colours.map((c, i) => (i === body.index ? locked : normaliseHex(c.hex)));
    if (!hexes.every((h): h is Hex => Boolean(h))) continue;
    const key = hexes.join();
    if (seen.has(key)) continue;
    seen.add(key);
    palettes.push({ name: p.name.slice(0, 40), colours: hexes.map((hex, i) => ({ hex, name: p.colours[i]!.name.slice(0, 40), role: roles[i]! })), why: p.why.slice(0, 300) });
    if (palettes.length === 3) break;
  }
  if (!palettes.length) throw new AiError("Couldn’t build palettes around that colour. Try again.", 502, false);
  return { palettes, model, usage };
}
```

```ts
import { getStyle, styles } from "../content/styles";
import type { Hex, PaletteRecord } from "../content/types";
import { normaliseHex } from "./color";

/** A typed hex, with or without #, 3 or 6 digits; null when it isn't one. */
export function parseHexInput(text: string): Hex | null {
  return /^#?([0-9a-f]{3}|[0-9a-f]{6})$/i.test(text.trim()) ? normaliseHex(text) : null;
}

/** The style a swap starts on: the one the visitor came from, else the palette's first suited style. */
export function initialSwapStyle(palette: PaletteRecord, s: string | null): string {
  if (getStyle(s)) return s!;
  return palette.suits.find((slug) => getStyle(slug)) ?? styles[0]!.slug;
}

export function swapBuilderHref(hexes: Hex[], style: string): string {
  return `/builder?pm=custom&c=${hexes.map((h) => h.slice(1)).join("-")}&s=${style}`;
}
```

```ts
export interface SwapReply {
  /** Up to three palettes, each keeping the visitor's colour in place. */
  palettes: { name: string; colours: { hex: Hex; name: string; role: PaletteRole }[]; why: string }[];
}

/** Rebuild a palette around one new colour, for one style. */
export function aiSwap(body: { style: string; colours: { hex: Hex; name: string }[]; index: number; hex: Hex }) {
  return post<SwapReply>("/api/swap", body);
}
```

```tsx
  const [style, setStyle] = useState(() => initialSwapStyle(palette, params.get("s")));
```

```ts
import type { Hex, PaletteColour, PaletteComposition, PaletteRecord, PaletteRole } from "../types";

export const p = (hex: Hex, name: string, role: PaletteRole, share: number): PaletteColour => ({ hex, name, role, share });

const ROLES: Record<number, PaletteRole[]> = {
  2: ["background", "primary"],
  3: ["background", "primary", "accent"],
  4: ["background", "primary", "secondary", "accent"],
};

/** A palette made for one style; roles follow the colour count. Colours are [hex, name, share]. */
export function stylePalette(
  style: string,
  d: { slug: string; name: string; mood: string; description: string; composition: PaletteComposition; colours: [Hex, string, number][] },
): PaletteRecord {
  const roles = ROLES[d.colours.length];
  if (!roles) throw new Error(`${d.slug}: palettes have 2 to 4 colours`);
  return { slug: d.slug, name: d.name, mood: d.mood, description: d.description, composition: d.composition, suits: [style], colours: d.colours.map(([hex, name, share], i) => p(hex, name, roles[i]!, share)) };
}
```

```ts
export function filterPalettes(list: PaletteRecord[], size: PaletteSize | null, q = "", style: string | null = null): PaletteRecord[] {
  const terms = fold(q).split(/\s+/).filter(Boolean);
  return list.filter((p) => {
    if (size && p.colours.length !== size) return false;
    if (style && !p.suits.includes(style)) return false;
    if (!terms.length) return true;
    const hay = fold([p.name, p.mood, p.description, ...p.colours.map((c) => `${c.name} ${c.hex}`)].join(" "));
    return terms.every((t) => hay.includes(t));
  });
}
```

### Task 5: Write the palettes, one family at a time

Do this once per family file, in order: `movements` → `print` → `retro` → `digital` → `craft`. Each family is its own commit. These palettes are written by hand here, using the style records; **no script or API call generates them**.

**Rules for every palette** (the content test enforces the first five):
1. Four per style in the family (`stylePalette("<slug>", …)`); count palettes in `library.ts` that already suit the style, but still add four new ones so each style has a full set of its own.
2. Sizes per style: one 2-colour, one 3-colour, two 4-colour.
3. Shares total 100; background largest (40–80), accent smallest (8–20).
4. Upper-case six-digit hex, no repeats inside a palette.
5. `contrastRatio(background, primary) >= 3`.
6. Slugs: `<style-slug>-<word>` (e.g. `art-deco-gilt-night`), unique.
7. True to the style's period, materials, printing and pigments (no vaporwave pastels for Art Deco); different from each other and from the style's own `swatches` (the swatches are already shown on the style page).
8. Usable on screens: think of each as a website or poster system: background as page, primary as text and main shapes, accent for buttons and highlights. Lean on colour directions designers are using now (warm off-whites instead of pure white, deep inks instead of pure black, one saturated hero colour) where the style allows it.
9. `name`: 1–3 words; `mood`: three adjectives, comma-separated, first capitalised; `description`: one or two plain sentences naming the colours and saying where they work; `composition`: one of `fields`, `arch`, `stripes`, `orbit`, `steps`, `split`, `window`, `wave`, chosen to suit the style's forms (e.g. `arch` and `steps` for Art Deco, `stripes` for op art).
